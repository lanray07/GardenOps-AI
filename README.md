# GardenOps AI

GardenOps AI is a React Native Expo MVP for planning a garden, generating mock AI planting plans, tracking tasks, scanning plants, and estimating potential crop value.

## Stack

- React Native with Expo
- TypeScript
- React Navigation bottom tabs
- Firebase JS SDK placeholder for Auth and Firestore
- AsyncStorage local persistence with optional Firebase sync
- Expo Image Picker for plant photo selection
- Expo IAP for Apple subscription purchases
- JSON data export through Expo FileSystem and native sharing
- Mock-first AI planner with optional backend endpoint in `services/openAiGardenApi.ts`
- Mock-first smart weather tasks with optional backend endpoint in `services/weatherTasksApi.ts`
- Mock-first plant scanner with optional backend endpoint in `services/plantIdApi.ts`
- Branded app icon, adaptive icon, favicon, splash image, and reusable in-app brand mark

## MVP Notes

- All plans, tasks, crop value rows, and scanner results use mock data.
- Onboarding answers, completed tasks, and the latest AI plan are saved locally with AsyncStorage.
- Add real OpenAI planning through a secure backend and set `EXPO_PUBLIC_AI_PLANNER_ENDPOINT`.
- Add Firebase keys with `EXPO_PUBLIC_FIREBASE_*` environment variables to enable anonymous Auth + Firestore sync.
- Add real weather-aware task generation through a secure backend and set `EXPO_PUBLIC_WEATHER_TASKS_ENDPOINT`.
- Plant Scanner can choose and preview an image; add Plant ID API analysis in `services/plantScanner.ts`.
- Account mode is local demo by default and becomes Firebase-ready when Firebase env vars are present.
- Settings includes a Firebase demo sync sign-in button when Firebase env vars are present.
- Premium gates use Apple subscription product IDs from `monetisation.ts`: one free AI plan, locked Profit Mode, and locked smart weather tasks.
- TODO: Add server-side App Store receipt validation before relying on subscriptions for production revenue enforcement.
- Settings can export a JSON snapshot with profile, tasks, latest AI plan, profit rows, subscription, and sync status.
- Add Apple In-App Purchases in `monetisation.ts` and replace the local Settings toggle before launch.

## Firebase Setup

1. Copy `.env.example` to `.env.local`.
2. Fill in your Firebase web app values.
3. Enable Anonymous Auth in Firebase Authentication.
4. Create a Firestore database.
5. Replace the MVP Firestore rules with user-owned rules before shipping.
6. Use Settings -> Continue with Firebase demo sync to test anonymous Auth.

## AI Planner Endpoint

Keep OpenAI API keys on a trusted backend. The Expo app can call a backend by setting:

```bash
EXPO_PUBLIC_AI_PLANNER_ENDPOINT=https://your-domain.com/api/garden-plan
```

The app sends a `POST` body shaped like:

```json
{
  "gardenSize": 4,
  "sunlight": "Medium",
  "location": "Bristol, UK",
  "preferredCrops": ["Basil", "Lettuce"],
  "budgetGbp": 30
}
```

The endpoint should return:

```json
{
  "recommendedCrops": ["Basil", "Lettuce"],
  "plantingSchedule": ["Week 1: Prepare containers"],
  "wateringSchedule": ["Check soil moisture every morning"],
  "estimatedHarvestTime": "2 to 6 weeks",
  "estimatedYield": "4 to 8 fresh portions per week",
  "estimatedValueGbp": 42,
  "notes": "Generated by your OpenAI-backed planner."
}
```

If the endpoint is missing or fails, the app falls back to the local mock planner.

## Weather Tasks Endpoint

Keep weather API keys on a trusted backend. The Expo app can call a weather task backend by setting:

```bash
EXPO_PUBLIC_WEATHER_TASKS_ENDPOINT=https://your-domain.com/api/weather-tasks
```

The app sends a `POST` body shaped like:

```json
{
  "profile": {
    "location": "Bristol, UK",
    "gardenType": "Balcony",
    "sizeSquareMetres": 4,
    "sunlight": "Medium",
    "goal": "Grow Food"
  },
  "existingTasks": []
}
```

The endpoint should return an array of tasks:

```json
[
  {
    "id": "weather-water-containers",
    "title": "Water containers before the warmest part of the day",
    "dueDate": "Today",
    "priority": "High",
    "completed": false
  }
]
```

If the endpoint is missing or fails, the app falls back to local mock smart tasks.

## Plant ID Endpoint

Keep Plant ID provider API keys on a trusted backend. The Expo app can call a plant scanner backend by setting:

```bash
EXPO_PUBLIC_PLANT_ID_ENDPOINT=https://your-domain.com/api/plant-id
```

The app sends a multipart `POST` request with an `image` file field. The endpoint should return:

```json
{
  "plantName": "Basil",
  "confidenceScore": 0.92,
  "careInstructions": [
    "Keep in bright indirect light.",
    "Water when the top 2 cm of soil feels dry."
  ]
}
```

If the endpoint is missing or fails, the app falls back to the local mock scanner.
